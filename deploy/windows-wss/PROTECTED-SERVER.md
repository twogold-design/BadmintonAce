# 带流量保护的服务器

完整服务器包 `BadmintonAce-Protected-Server-年月日-时分秒.zip` 包含新版游戏后台 EXE、Caddy 加密入口和统一启动器。无需安装 Node，不包含游戏资源、玩家数据或证书。

运行工程的 `tools/build.ps1` 会更新 `dist/BadmintonAce-Web.zip`（给玩家），仅当服务器代码、依赖、云端配置或启动脚本等部署文件发生变化时，才新增带北京时间的服务器包，例如 `dist/BadmintonAce-Protected-Server-20261102-180000.zip`。只改游戏画面、操作或客户端时不重复生成服务器包。旧包全部保留，由使用者自行删除；按文件名时间选择最新包即可。包内 `RELEASE.json` 记录该次服务器发布的生成时间、文件名及当时客户端校验值；后续仅客户端更新时，仍可沿用该服务器包。单独检查并更新后台可运行 `tools/build_protected_server.ps1 -IfChanged`；不加参数可手动强制打包。

## 从现有服务器升级

本地可直接拷贝的目录固定为 `build/BadmintonAce-WSS-Windows`，其中直接放置 EXE、启动脚本和配置，不再套随机命名的外层文件夹。压缩包内也只有这一层 `BadmintonAce-WSS-Windows`。打包临时文件放在 `.runtime`，旧压缩包继续保留。

1. 在云服务器上关闭原来的游戏后台 EXE 和 `start-wss.cmd` 窗口。保留原后台旁的 `data` 文件夹（账号与排行榜）。
2. 将完整包解压到原来的 WSS 文件夹，允许替换同名程序和脚本；**保留其中的 `wss-state` 文件夹**，继续使用原有证书。若后台也在这个目录，务必先关闭再替换。不要只复制 EXE。
3. 双击 **`start-protected.cmd`**。第一次会弹出文件选择框，选择之前使用的 `BadmintonAce-Server.exe`，用于找到它旁边的 `data` 文件夹。启动器实际运行的是本包中的新版 EXE。若选择的是错误目录，请退出并更正 `wss-state/guard-settings.json` 中的 `dataDirectory`，避免看见空排行榜。
4. 保持这个监测窗口打开即可；它会自动启动后台和 WSS，不要再单独启动 EXE 或 `start-wss.cmd`。
5. 打开 `https://121.40.81.89/health`，应无证书警告并显示 `ok:true`、`trafficGuardControl:true`；再用两名玩家测试创建和加入房间。

如果解压到了新目录，还需将旧 WSS 目录的 `wss-state` 完整复制到新目录来保留证书，并在云端以管理员身份运行新目录的 `allow-wss.cmd`，因为防火墙规则关联程序路径。阿里云安全组仍需允许 TCP 80/443；无需为此修改远程桌面规则。WSS 验证成功后建议关闭后台 8766 的公网放行。IP 变化需同步更新 Caddyfile 两处 IP 和玩家包配置。完整证书说明见 README.md。

## 默认保护

新版后台默认与支持的浏览器协商 WebSocket 无损压缩，减少重复状态和控制数据的传输；不支持压缩的客户端仍可正常连接。玩家也更新游戏包后，方向未改变的移动指令和冻结画面的重复状态会减少发送，正常回合仍保持每秒 30 次状态同步，击球、转向和松键立即发送。

压缩采用低等级和受限并发，仍会增加少量 CPU 开销。若需要对照排查，关闭监测窗口后，在此目录终端运行 `start-protected.cmd -NoCompression`，即可临时关闭压缩；普通双击启动恢复默认。超限恢复时可使用 `resume-protected.cmd -NoCompression`，不会取消流量保护。后台单独运行时，对应环境变量为 `ACE_WS_COMPRESSION=0`。不要同时运行两个启动器。

任一条件满足就停止本启动器管理的游戏后台和 WSS：

- 最近约一小时出站达到 **1 GB**（十进制 1,000,000,000 字节）。采用分钟桶，保守覆盖最近 60～61 分钟。
- 出站平均速率连续 **30 秒超过 5 Mbps**。默认每秒采样一次；短于采样间隔的瞬时峰值不单独触发。
- 运行中读取网卡、保存流量记录失败，或任一受管理程序退出。

流量仍每秒检测一次；常规状态在启动后显示一次，之后每 5 分钟显示一次，避免频繁刷屏。启动、异常和超限停服提示立即显示，不受状态输出间隔影响。

这不是阿里云账单计量：默认统计带 IPv4 默认网关的活动网卡全部出站，包括远程桌面、其他程序及内网流量。不能仅凭本工具保证流量费不超额。一次采样和停服期间仍会有少量新增流量。它不关闭网卡或云服务器，其他程序和云端攻击流量不受此保护控制。

阈值写在 `traffic-limits.json`，停止启动器后修改、重新启动生效。`adapterNames: []` 自动选择网卡；只有明确知道服务器网卡配置时才手动填写名称。不要为了临时恢复而删除历史记录。

## 超限后与恢复

触发后不会自动重新启动；原因记录在 `wss-state/logs/traffic-guard.log`，停服标记及小时用量保存到 `wss-state/traffic-state.json`，重新双击普通启动器不能绕过。

排查流量来源后，双击 **`resume-protected.cmd`** 并输入 **`START`** 确认恢复。小时用量仍保留：尚未降到阈值以下时会继续拒绝启动。持续高流量计时从新一轮监测开始；重启 Windows 或网卡计数器重置后也可能需要此恢复入口重新建立计数基线。

正常关闭监测窗口会同时关闭两项服务；强制关闭时由 Windows 回收其管理的进程。要继续保护，必须始终使用受保护启动器；手动单独打开旧 EXE 或 `start-wss.cmd` 不会受到它的保护。没有设置开机自动启动，Windows 重启后需再次双击。

超限时后台会先正常断开对局，尽量避免误记逃跑；未完成比赛不结算，已保存的账号、积分不删除。强制断电或强杀窗口不能保证完成正常关闭过程。

**ECS 仍保持开机，云服务器租用和磁盘等费用不因游戏停服而停止。**

## 文件与日志

- `start-protected.cmd`：日常统一启动。
- `resume-protected.cmd`：处理原因后手动恢复。
- `traffic-limits.json`：阈值设置。
- `wss-state/logs/backend-*.log`：游戏后台日志。
- `wss-state/logs/caddy-*.log`：WSS 与证书日志。
- `wss-state/guard-settings.json`：原玩家数据路径。

`wss-state` 中含证书私钥和运行状态，不要公开或提交到 GitHub。不要删除原 `data`、`rankings.sqlite`、`gm-key.txt`。重复启动或已有程序占用端口时，启动器会报错退出，不会擅自关闭其他程序。
