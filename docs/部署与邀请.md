# 跨地点联机部署与邀请

> 当前默认采用局域网模式，优先阅读 `局域网使用说明.md`。公网功能默认关闭；下面是可选部署资料。如以后主动启用公网，须在启动前设置 `LAN_ONLY=0`，并把代理目标端口调整为 8766，源码运行需要 Node.js 24。Windows 用户直接使用 EXE，无需安装 Node.js。

当前交付的是可部署版本，尚无公网服务。两位玩家分别在不同地点时，不能互相使用 `127.0.0.1`，也不能将 `ws://…/ws` 当网页链接打开。

## 方案一：自己的电脑开主机，朋友点链接加入

当前版本支持在你的电脑运行房间服务，由房主浏览器计算比赛状态。要让异地朋友访问，还需要一个公网 HTTPS 入口。内网穿透可以提供这个入口，不需要先租云服务器；网络流量会经过穿透服务，不是完全点对点直连。

1. 在本项目目录双击 `开始游戏.cmd`，启动本机游戏服务。确认 `http://127.0.0.1:8766/health` 显示 `ok: true`。
2. 选择支持 HTTPS 和 WebSocket 的穿透服务，将公网地址映射到本机 `http://127.0.0.1:8766`。应映射整个网站，包括 `/ws`，不要只映射首页。
3. 例如使用 Cloudflare 的固定 Tunnel，需要 Cloudflare 账号和接入该账号的域名。按照其官方教程创建 Tunnel，在这台电脑运行连接程序，再添加 Published application 路由：公网域名填写自己的游戏域名，Service URL 填 `http://127.0.0.1:8766`。连接程序、配置与日志请保存到本项目的 `.runtime` 内；不必安装成系统服务。
4. **你自己也通过公网 HTTPS 地址打开游戏**，不要从原来的 localhost 页面开房。服务会根据代理转发的 HTTPS 请求生成邀请；若代理未传递协议信息，则需在启动 Node 服务前设置 `PUBLIC_URL` 为该公网 HTTPS 地址，并重启房间服务。
5. 点击“在线对战”→“创建房间”→“复制邀请”，将网页链接发给朋友。朋友只需浏览器，不需要安装 Godot、Node 或穿透程序。
6. 对局期间保持你的电脑、房主页面、房间服务和穿透连接运行。主机睡眠或退出后，朋友会断开。

固定 Tunnel 官方教程：https://developers.cloudflare.com/tunnel/get-started/
WebSocket 支持说明：https://developers.cloudflare.com/cloudflare-one/faq/cloudflare-tunnels-faq/

若要真正直接访问你家的公网 IP，则要求运营商提供可入站的公网地址，路由器与防火墙允许对应流量，并配置可信 HTTPS。仅把局域网 IP 或 `127.0.0.1` 发给朋友无效。当前游戏没有实现浏览器 WebRTC 点对点连接；这类方案仍通常需要信令服务，部分网络还需要中继。

本版本未配置或启动公网穿透，也未验证跨地点可达性。穿透服务的可用性和延迟取决于双方网络，正式比赛更适合固定服务器部署。

## 方案二：部署完整游戏服务到公网服务器

解压 `BadmintonAce-Server.zip`。目录包含 `server/`、`build/web/`、Dockerfile 和说明文件。准备一台有公网访问能力的服务器，以及用于 HTTPS 的域名或托管平台域名。

直接使用 Node.js（20 或更高版本）：

```sh
npm ci --prefix server --omit=dev
PUBLIC_URL=https://你的实际域名 PORT=8766 node server/server.js
```

服务进程应由服务器的进程管理工具保持运行。把实际域名的 HTTPS 流量反向代理到 `127.0.0.1:8766`，并允许 WebSocket 连接。项目的 `server/Caddyfile.example` 可供改写。客户端连接使用 `wss://实际域名/ws`。

也可以使用 Docker，在解压目录执行：

```sh
docker build -t badminton-ace .
docker run -d --name badminton-ace --restart unless-stopped \
  -p 127.0.0.1:8766:8766 \
  -e PUBLIC_URL=https://你的实际域名 badminton-ace
```

Docker 示例仍需由宿主机提供 HTTPS 反向代理。镜像不包含仅供本地双击使用的冗余资源包，网页正常从标准 Godot 文件加载。

## 创建和使用邀请

1. 双方均用支持 WebGL 2 的桌面浏览器访问 `https://实际域名/index.html`。
2. 房主点击“在线对战”→“创建房间”。界面应显示“公网邀请”。
3. 点击“复制邀请”，分享形如 `https://实际域名/index.html?room=ABC123` 的网页链接。
4. 朋友打开链接，游戏会使用该网页的服务自动加入房间，无需另外粘贴 WebSocket 地址。
5. 房主保留页面，双方开始比赛。关闭房间或服务重启后，旧邀请失效，需要重新创建。

若没有出现可复制的邀请：检查服务的 `PUBLIC_URL` 是否是实际可访问的 HTTPS 域名。当前连接仅为本机或局域网时，界面会明确提示并禁用无效的跨地点邀请。

## 比赛平台只支持静态网页时

将 `BadmintonAce-Web.zip` 上传平台，入口选 `index.html`。联机服务仍需独立部署。将 `build/web/config.js` 的 `window.ACE_SERVER` 设置为该服务的 `wss://实际域名/ws`，再重新压缩发布文件。建议完整服务也托管游戏网页，因为邀请链接默认指向该服务自己的 `/index.html?room=...`。

## 部署后检查

- `https://实际域名/health` 返回 `ok: true`。
- 从另一网络打开游戏网页，并确认浏览器控制台没有资源加载错误。
- 创建房间后，邀请必须以 `https://` 开头，含六位 `room` 参数，不能是 `127.0.0.1`、`localhost` 或局域网 IP。
- 两个浏览器通过邀请进入同一房间，双方移动、击球和得分同步。

项目内测试已覆盖房间邀请格式、自动加入、无效地址提示和本地双浏览器对战。尚未执行实际公网部署，公网可达性和跨地域延迟需在部署后验证。
