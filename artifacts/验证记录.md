# 验证记录

验证环境：Windows，指定的 Godot 4.7.2，Chrome WebGL 2；全部测试资料存放在项目目录。

- 回球随机化后，原生引擎自动 AI 对打完成一局：5:3，142 次击球，最长 40 拍；本局 8 次落地得分，没有下网或出界。
- 45 项机制检查通过：四种主要球路可合法过网落地；拒绝重复触球；对角发球；下网及出界判分；11/21 分制的领先两分及封顶；跳跃/蹬步体力消耗；吊球两侧与同侧变化、合法过网、停步保留方向、深浅选择、远场方向和对手空位选择。
- 回球随机化专项检查通过：固定随机种子，256 次近场/远场高远、杀球、平抽及挑球的完整飞行均合法过网落地；同样站位和蓄力能覆盖两侧并变化深浅，自动落点避免连续重合。另验证手动左右瞄准、双方深浅方向、空位偏好，共 1015 条断言。详见 `shot-variation-test.json`；这是指定击球条件下的验证，不代表所有低位、后场杀球都能过网。
- 房间服务检查通过：创建、加入、不存在/已满房间、操作和状态转发、角色权限、暂停、重赛消息、断线清理。
- 两个独立 Chrome 浏览器实例实际加载最新 Godot 网页：房间创建、从空闲房间列表选择并进入、房主发球、加入者移动及回球、比分一致、双方暂停/恢复、掉线提示均通过；无浏览器脚本错误。
- 邀请逻辑检查通过：本机、局域网和公网范围判断；拒绝生成 loopback / 局域网 HTTP / 公网 HTTP 邀请；配置公网 HTTPS 域名后生成网页邀请。最新服务在独立测试端口 18765 验证，未重启原有 8765 服务。
- 已检查主页、比赛和房间页面的截图，修正字体字重和高球被比分栏遮挡的问题。
- 浏览器内 AI 成功接回玩家发球；操作指南与 1280×800 暂停界面检查通过。
- 已查看最新比赛截图：近场角色显示后脑和背号，远场角色显示面部，双方朝向球网；球衣、鞋袜、四肢与球拍细节可见。
- 网页发布包 `BadmintonAce-Web.zip` 根目录包含 `index.html`。加入本地直接打开兼容资源后，解压约 84.59 MB，压缩约 47.31 MB，均低于 200 MB。
- 修复直接双击 HTML 时的 `Failed to fetch`：使用配套压缩资源加载引擎和游戏数据，音频处理器从内嵌内容加载；本地文件模式跳过不支持的 PWA 更新检查。
- 项目根目录 file: 入口、导出目录 file: 入口和 HTTP 入口均已实际进入游戏，玩家发球和 AI 回球通过，无浏览器脚本错误；HTTP 模式确认不会请求本地兼容资源包。未关闭浏览器安全选项。记录见 `local-entry-test.json`。

以上联机验证在同一电脑的两个独立浏览器中通过本地房间服务完成；尚未在两台物理电脑、真实公网延迟、比赛平台的 iframe 环境进行实测。公网服务尚未部署，Docker 镜像未实机构建；已提供 Dockerfile、HTTPS 反向代理示例和自托管/穿透说明。当前为键盘桌面游戏，没有触屏操作。
