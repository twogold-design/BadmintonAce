# 谁是羽毛球高手

Godot 4.7.2 制作的 3D 网页羽毛球游戏，支持单人 AI、练习和两台电脑的局域网 1v1。网页参赛包根目录包含 **index.html**，构建脚本会检查解压及压缩后均低于 200 MB。项目、构建、缓存和测试文件均存放于本目录。

## 从 GitHub 获取

仓库包含 Godot 工程、游戏与服务器源码、模型、字体及许可，以及可直接游玩的 `build/web/` 网页文件。**同伴拉取最新版，或下载 Code → Download ZIP 并完整解压后，直接打开根目录 `index.html`，点击“单机游玩”即可玩。无需安装 Godot、Node.js，也无需自己导出。** 请保留整个 `build/web/` 文件夹，不能只复制一个 HTML。

根目录入口自动进入随仓库提供的网页版本；登录和局域网对战仍需可访问的游戏服务器，单机挑战和练习无需服务器。独立试玩包也可从 [版本下载页](https://github.com/twogold-design/BadmintonAce/releases) 获取 `BadmintonAce-Web.zip`；自建局域网主机使用包含服务器 EXE 和配套网页的 `BadmintonAce-Server.zip`。

修改源码时仍可用 Godot 4.7.2 导入 `project.godot` 并按 F5 调试。修改后需要更新浏览器版本时，运行 `重新导出网页版.cmd`，将生成的 `build/web/` 更新与源码一起提交。其他构建输出、`dist/`、服务器 EXE、依赖目录、缓存及玩家数据库不纳入版本管理。

开发时用 Godot 4.7.2 打开 `project.godot`。可直接编辑的新角色 `.blend`、运行时 `.glb`、原始网格、纹理、授权与重建脚本均包含在仓库中。协作分工、安装、测试和重新导出步骤见 [协作开发指南](CONTRIBUTING.md)。常规游戏开发不需要安装 Blender。

Windows 工具路径可用 `GODOT_BIN`、`NODE_BIN`、`ACE_BROWSER` 环境变量指定，也支持从 PATH 查找。先运行 `tools/environment.ps1`，缓存、临时文件和依赖下载均留在项目的 `.runtime` 中。

## 开始游戏

完整解压 `dist/BadmintonAce-Web.zip`，用 Chrome / Edge 双击 **index.html**，在登录页点击“单机游玩”即可离线挑战和练习，无需账号或服务器。需要积分和在线对战时再登录，首次登录自动创建球员账号。打开页面不会自动登录或连接服务器。不需要安装 Godot。请保留所有配套文件，不能单独发送 HTML。项目根目录的入口引用 `build/web/`；参赛 ZIP 的入口与资源在同一级。

网页也可上传支持 WebGL 2 的 HTTPS 比赛平台，入口选择 index.html。单机模式无需联机服务；积分和在线对战需配置可访问的服务地址，静态网站本身不能运行账号和房间服务器。

## 账号与积分

账号名为 2–16 个汉字、字母、数字、下划线或短横线，密码至少 3 位。使用同一服务器上的账号和密码可在其他电脑登录，积分和挑战奖励归属账号。密码使用独立盐值和 scrypt 哈希保存；本地只保存会话凭证，不保存密码。

“开始挑战”可以选择石宇奇、安塞龙、周天成、昆拉武特、安洗莹、陈雨菲、王祉怡、山口茜八位 AI 对手。挑战不限次数，每位对手仅首次获胜奖励 **5 积分**，八位共 40 分；失败和重复获胜不加分。对手使用对应男女角色外观，不是运动员真人模型。自由练习不加分。

在线 1v1 每场获胜奖励 **10 积分**，失败不加分。中途退出判负时，对手同样获得 10 积分。首页顶部的“积分排行榜”按钮可展开按总积分排序的榜单并实时更新；积分结算有唯一记录，重复提交不会重复加分。旧游客记录保留在数据库，新注册账号从零积分开始。

## 局域网房间与排行榜

主机运行 `BadmintonAce-Server.exe`，无需安装 Node.js。默认端口 **8766**。主机第一次需右键 `允许局域网联机.cmd` → **以管理员身份运行**，仅允许本地子网访问这个 EXE 的指定端口，不关闭防火墙。也可双击 `开始游戏.cmd`，后台启动服务并打开主机游戏。

- 玩家一：打开游戏 → 在线对战 → 右侧创建房间（密码可留空），自己的房间立即显示在左侧列表。
- 玩家二：打开游戏 → 在线对战 → 在左侧空闲房间列表选中房间 → 加入选中房间。
- 公开房直接进入，密码房输入密码后进入。列表实时更新，满员或关闭的房间自动移除；房主可点击“关闭我的房间”取消等待。
- 首页顶部点击“积分排行榜”展开本服务器榜单，点击“收起”或按 Esc 关闭；默认不遮挡首页演示。

下载版已预设当前主机 `10.11.179.27:8766`，普通玩家无需输入地址或房间码。主机 IP 改变时，由组织者修改网页包的 `config.js`；发包前可修改 `build/web/config.js`，开发用配置源为 `tools/web-config.js`。在线对战页不提供连接设置。建议在路由器给主机保留固定内网 IP。旧版客户端和 8765 服务不要与新版混用。

详细主机准备、排错与备份见 [局域网使用说明](docs/局域网使用说明.md)。对战采用 **WebRTC 数据通道直连**，房主计算比赛，飞行中最高 30 Hz 同步；WebSocket 服务器仅负责账号、积分、房间、少量直连协商和最终结果，不转发移动、球、动作或暂停。独立二进制快照约 420–460 字节，球与速度保持 float32 精度，序号丢弃过时帧，B 端统一时间轴缓冲显示。角色仅在开局交换，移动变化时发送并定期补发；击球、暂停、结果状态走可靠直连通道。

当前直连限定可互通局域网，不使用 TURN，也不会退回服务器转发。双方直连成功才开赛；建立失败不计分。比赛结束前先退出或被服务器确认断线的一方判负，对手判胜，房主同样适用。服务器已收到最终比分后退出保留原结果。仅 P2P 路径断开、双方账号连接仍在时无法判断退出方，会取消比赛而不误判；服务器关闭不判玩家负。服务须持续运行，数据库 `data/rankings.sqlite` 保存账号与积分；重启保留榜单，不保留房间。

首页演示使用与对战相同的步伐和触球动画；身体、落脚点和羽毛球共享时间轴，连续引拍、触球与回位。球拍拍面为透空的细网线结构。

## 角色选择

主菜单点“角色 · 男 / 女”，查看男女角色的正面与背面预览，直接点击对应角色卡片进行选择。在线对战页沿用主菜单选择，不再提供角色切换。选择自动保存，单人、练习和在线对战均生效，联机双方同步各自角色。女性角色有清爽高马尾、短袖运动球衣、运动短裤和随动作摆动的发梢。男女速度、体力、跳跃与击球范围相同，只改变外观。单人陪练使用另一款角色。

## 操作与视角

| 操作 | 按键 |
|---|---|
| 移动 / 蓄力时指定方向 | WASD |
| 放网 / 吊球 | J |
| 杀球 / 平抽挡 / 网前推球 | K（依高度与位置变化） |
| 高远 / 低位自动挑球 | L |
| 跳跃 / 配合 K 跳杀 | Space |
| 蹬步救球 | 左 Shift |
| 预计轨迹 / 落点 / 高度参考线 | H |
| 底线视角 / 俯视视角 | C |
| 暂停 / 操作指南 | Esc |

默认使用拉近的低位底线镜头，按参考图的室内赛场构图放大球场与角色。高球升起时镜头适度放宽并平滑恢复，保持真实投影。比分为左上两行、右上显示本方体力和暂停；场内地胶保留原来的绿色，场外为深色缓冲区；场边有广告围挡、裁判高椅及坐席。比赛仍为 1v1，品牌字样和场景由本工程制作，没有使用参考游戏的素材。

窗口变化时三维场景铺满实际宽高比，按钮、文字和图标使用统一缩放系数，避免被横向/纵向拉长。L 在实际触球时按球相对选手的高度选择高远或挑球，K 选择高点击杀/低位平抽，J 为放网/吊球；发球用 L 发高远或 J 发短球，I 不再击球。联机由房主按真实触球高度决定球路。

主要按键提示位于屏幕底部中央。羽毛球采用约 8.6 厘米长的三维模型：16 片薄羽片、羽轴、绑线和球头，配合较细尾迹；模型外观尺寸不改变原有击球判定。

实线尾迹表示已飞过的路线，细弧线表示未被拦截时的预计路线，落点圈帮助判断接球位置，不显示落地时间。对手回球后预测会重新计算，预计轨迹不保证来球一定能过网。H 关闭预测辅助后仍保留球尾迹。

**按住蓄力，松开挥拍。** 可轻点接球，不需要每球长蓄力。脚下亮环表示进入击球范围；靠近球并短蓄力 0.1–0.5 秒可打中甜区。松键后有 0.36 秒输入缓冲；网前低球和快速下压球差一小步时，按住或轻点击球键可触发一次短跨步救球，向来球移动时也可辅助；反向移动立即取消，远球仍需提前跑位。普通来球保留松开方向后的轻微补步。移动时有支撑脚落地、小步调整、侧向并步与后退步；网前球和蹬步表现为持拍脚跨步。高远和杀球蓄力时前后错步侧身，击球后髋部先转、肩部随转，并表现重心转移与回正；跳跃高点挥拍带剪式换脚及落地缓冲。男女角色和 AI 使用相同的程序动作。

**指定球路**：蓄力时 A/D 选左右，W/S 选深浅，停步后保留选择。方向按自己的画面对应：W 向球网，S 向底线，A/D 向画面左右。蓄力时 W 为深球、S 为浅球，双方一致。吊球蓄力时显示目标圈。不指定方向时，回球会结合对手站位选择空位或追身，并变化左右与深浅，减少连续相同落点；手动瞄准优先。杀球仍受高度影响，太低、太晚可能下网。

联机双方使用相同按键，各自都从自己的底线看球场，自己的角色背对镜头。P2 画面与方向输入旋转 180°，无须反向操作。P2 使用约 66 毫秒的画面缓冲，让球的位置、速度、步伐和转体按同一时刻显示，减少轨迹跳动；这不消除实际网络延迟，严重丢包时仍可能停顿。暂停同步给双方，失去焦点会暂停，一方可恢复比赛。双方镜头选项互不影响。

## 规则与范围

动作已按真人教学顺序重新组织：肩、肘和球拍分开运动，头顶击球后跨身随挥，再平滑回到准备姿势；膝盖朝脚尖方向弯曲，并步不交叉。高位吊球与网前球采用不同动作。参考资料和实现范围见 [动作参考与实现](docs/动作参考与实现.md)，[3D 动作分解图](artifacts/motion-reference-sheet.png)。

单打内边线，落地得分，下网 / 出界失分。赢球方发球，随得分奇偶交换左右发球区。所有比赛固定为 11 分制，领先 2 分获胜、15 分封顶，不提供分制切换。AI 有三档难度。

这是偏街机操作的程序动画游戏，未使用动作捕捉或 Pure Badminton 素材。比赛规则简化为单局决胜，没有鹰眼挑战、交换场地或正式多局赛制。已提供账号和积分系统；排行榜为休闲用途，未实现断线续局或竞技级反作弊。AI 和房主上传的结果仍依赖客户端诚信，服务器负责账号校验和防止重复计分。

## GM 账号管理

服务器本机可双击 `GM管理.cmd`，查看账号，并对单个或全部账号清除积分、删除账号。修改前自动备份，需输入确认文字；受影响账号退出登录，相关对局取消但不判负。详见 [GM 管理](docs/GM管理.md)。

登录页仅提供“登录”和“单机游玩”。首次使用账号名和密码时自动创建账号，已有账号必须使用原密码。单机挑战不计入账号积分。长短发球统一使用反手；后场近左侧高球优先使用头顶正手，较远才切换反手。

## 发布与开发

- `dist/BadmintonAce-Web.zip`：网页参赛包，入口 index.html。
- `dist/BadmintonAce-Server.zip`：主机部署包，包含独立 Windows EXE、网页及使用说明，不包含玩家数据。
- `project.godot`：源工程；`打开Godot编辑器.cmd` 使用可配置的引擎路径，并将缓存重定向到项目目录。
- `重新导出网页版.cmd`：导出、加入本地双击支持、压缩并校验 200 MB 上限。
- `dist/manifest.json`：发布文件体积与 SHA-256；`artifacts/验证记录.md`：实际验证及限制。
- `local-data.js` 仅在本地 file: 模式读取，网站托管不重复下载。

服务器默认接受所有可访问主机 TCP 8766 端口的玩家，不要求同一子网。园区不同网段可以接入账号、房间和排行榜；开赛还需要两台玩家电脑之间允许 WebRTC 直连通信。更新旧主机后，重新以管理员身份运行 `允许局域网联机.cmd`，取消原防火墙规则的本地子网限制。普通内网 HTTP 游戏页不满足安全上下文要求，其他电脑应使用完整本地游戏包。目前没有部署公网入口，也没有 TURN 转发；未来公网部署见 `docs/部署与邀请.md`。

角色基础网格、绑定与部分发型来自 Quaternius 的 CC0 Universal Base Characters，已改为运动员体型、运动服和清爽马尾；见 [角色来源与重建](assets/athletes/README.md)。球场、球拍、运动服着色、马尾网格、程序动作与合成音效由本工程实现；字体许可见 `assets/FONT-LICENSE.txt`，Godot 许可见 `docs/GODOT-LICENSE.txt`，服务端 Node.js 及其第三方许可见 `docs/NODE-LICENSE.txt`。
